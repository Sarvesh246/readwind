# PDF import reliability

New imports use a detected contents page to define chapters. Numberless linked lists, wrapped titles, numbered OCR rows and contents group headings are supported. Entries are matched to printed page labels, grouped opening headings, and internal PDF links. PDF bookmark titles can repair damaged text at a verified link destination. Conflicting or unresolved entries produce a review warning instead of an estimated chapter start. Nested PDF bookmarks are the fallback when there is no detected contents page; conservative typography detection is the final fallback.

Contents rows remain separate, clickable entries in adjustable text, including Curl, Slide and Scroll. Group headings and printed page references are retained. Original-layout PDF links also work. Both readers share searchable chapter navigation, and mobile readers expose Contents even on the closed cover. Reflow navigation skips empty source blocks, scroll navigation aligns the chapter heading, and spread-view chapter names and time follow the selected position rather than the previous chapter on the left page.

Already-imported flattened contents also receive a presentation-only repair. Chapter names and contents markers identify row boundaries while original paragraph strings, block indexes and character offsets remain unchanged. This avoids invalidating progress, highlights or page marks and does not require reimporting for the layout repair. Body paragraphs accidentally left in a Contents section are excluded from this treatment. Contents navigation does not train the reading-pace model.

Reading layout preserves explicit line breaks, indents block quotations, keeps subheadings with following text where space permits, and paginates unusually long words without losing characters. New PDF imports preserve OCR paragraph boundaries, recognize smaller native paragraph indents, and remove matching source heading lines when the chapter heading already displays them. Hyphen cleanup uses word forms elsewhere in the book to corroborate a joined spelling, retaining uncertain or established compound hyphens.

Printed page labels come from visible margin numbers or embedded PDF labels. Inline running-header numbers require corroboration on nearby pages; chapter-title numbers are excluded. Isolated OCR digit errors require neighboring numerical evidence, while native printed values are retained. Missing Arabic numbers are interpolated only between agreeing neighboring labels. Numbering gaps in the source are retained. Unknown numbers remain explicit labels such as `PDF 6`; they are not silently treated as printed page 6. Both reader modes resolve entered page labels uniquely, including Roman numerals, and reject missing or ambiguous labels.

The import review can add a chapter at a printed page, rename or merge chapters, and split at a paragraph. Titles expand to show their full text. Rows cannot shrink into each other, actions wrap on small screens, and paragraph editors load only when expanded. Splitting preserves the source blocks, figures, footnote references, and page anchors. Selecting a chapter's page opens its original preview. The preview supports correcting a single page label or explicitly numbering that page and all following pages. Numbering an entire remaining run is appropriate only when the source has no gaps or numbering resets.

OCR is enabled by default for sparse, missing, or visibly broken text layers. It uses bounded high-resolution rendering, automatic deskew, recognized line geometry, and a higher-resolution contrast-adjusted retry for uncertain output. A retry must improve the quality score without losing substantial recognized text. Readable native page numbers survive replacement of a sparse text layer. Confidence scores and extraction issues are available per page in the review. Language and cleanup options can be changed and the PDF reprocessed; this replaces review edits.

When OCR is unchecked, usable native text keeps the fast extraction path and optional visual comparisons stay off. A cheap raster check on sparse/textless pages looks for repeated text-like ink bands outside the native text's bounds. Clearly scanned text, including scan pages with only a selectable footer, enables OCR automatically for that page. Broken character mappings also force recognition. Blank pages and ordinary illustrations do not start OCR merely because they lack selectable text. The fallback uses the selected languages, reports its progress and records a notice in the import review. This is conservative detection; faint or unusual layouts can still need explicit OCR or original-page review.

Cleanup retains footnote text even when a reference cannot be linked, retains table text if a crop fails, protects large chapter headings from running-header removal, and avoids joining hyphenated text across column changes. Original PDF bytes remain attached. Imports with risky layouts or scanned content default to the recommended original mode, and users can choose adjustable text after reviewing it.

Native font metadata preserves bold and italic spans through cleanup, pagination, highlights and continuous reading. Short, strongly bold subheadings remain separate from body paragraphs. Linked contents continuations and headerless contents lists can be identified from corroborating PDF bookmarks; descriptive contents text stays separate from chapter names, and bookmarks supplement a partially resolved contents page.

Illustrations have no per-book count limit. Aligned financial tables with repeated numeric cells are preserved as page crops with their cell text attached for search. Text inside captured image regions stays with the image rather than becoming duplicate prose. Captured figures retain their aspect ratio and source page; select one to enlarge it or check its original page. Complex vector diagrams and unsupported table layouts still require original mode for exact presentation.

Sparse image-only opening pages retain their original design rather than displaying OCR mistakes as prose. Recognized text stays attached to the image for search. Longer scanned body pages still use adjustable OCR paragraphs. Clear sentence continuations across physical pages are rejoined only when the next page begins without a paragraph indent and starts in lowercase; page anchors retain their exact character offset. Manual chapter creation can split at those anchors while retaining styles and footnote references.

OCR confidence is an engine score, not a guarantee of transcription accuracy. Very faint, rotated, handwritten, multilingual, mathematical, or complex multi-column pages can still need review. Contents detection recognizes several language headings and common title/page rows; unsupported or ambiguous layouts can be corrected manually. Existing saved books are not automatically re-extracted, so their annotations and positions remain intact. Reimport a source PDF to use the new extraction behavior.

## Special layouts and fidelity checks

Automatic structure detection preserves verse, stanzas, code indentation, named speakers, stage directions, list items and nested list indentation. The measuring DOM, Curl/Slide pages and Scroll reader share the same layout rules. Structured blocks do not receive a drop cap or join across physical pages. In the import review, Text structure can explicitly preserve lines/stanzas, dialogue or code when automatic classification is uncertain; reprocessing applies that selection.

Aligned text-only tables are preserved alongside numeric tables. Equations, raised/lowered glyphs, complex multi-column layouts, mixed code/prose, rotated text, right-to-left text, vertical writing, low-confidence OCR and facing-page scans retain their original appearance inside adjustable text. Original-page rendering preserves their placement, symbols, writing direction and typography. It does not reconstruct semantic mathematics, editable table cells or vertical text flow. Source pages support enlargement and direct inspection of the PDF.

Source references render lazily from the saved PDF and release offscreen renderings, avoiding a PNG copy of every complex page. Password-protected imports keep unlocked page renderings for inline reading without persisting the password. Source pages retain searchable extracted text; when a reliable OCR comparison disagrees with a native layer, the recognized visible text is used for that page's search metadata. Search metadata can still contain recognition errors.

Exact overlapping text items are deduplicated for extraction and flagged for source preservation. Suspicious text layers trigger recognition. By default, OCR also compares the first substantive native page and regular samples against the rendered page; Every text page enables a slower full pass, and Off disables native-layer checks. Recognition can report matched, disagreed or inconclusive. Matched requires strong token and adjacent-word agreement; reordered text with the same word counts can disagree. This is not proof of every character or number. Uncertain results are never labeled matched. OCR replaces a sparse native layer only when it recovers meaningful additional words, preserving correct selectable tables whose geometry OCR would flatten.

An independent content-retention check compares each page's extracted source tokens with its constructed reading blocks. A substantial omission or any missing extracted numeric token replaces the reflowed page with its source appearance and records the reason. Numeric disagreement during a confident visual comparison also preserves the source; an isolated disagreement does not silently replace native amounts with OCR amounts. Quality review exposes recognition confidence, visual comparison results and source-preserved pages. Cropped or missing source content cannot be recreated from the PDF; source preservation retains what the file actually contains.

OCR language selection accepts multiple bundled languages: English, Spanish, French, German, Portuguese, Hindi, Arabic, Japanese and simplified Chinese. Select the languages used in a mixed-language book. Unsupported OCR scripts can still be read in original mode. The language selection is explicit rather than an automatic language-detection claim.

Horizontal Japanese/Chinese print lines join without inserting English spaces between CJK characters. Reading estimates use Unicode word segmentation for unspaced CJK text rather than counting a whole paragraph as one word. Word totals are cached per block so repeated progress calculations do not resegment the whole book.

Contents headings include French, German, Spanish/Portuguese, Italian, Russian, Chinese, Japanese, Korean, Arabic, Hebrew and Hindi forms. Detection can inspect contents later in the document. Headerless lists require corroboration from future destinations/headings; backward citations in endnotes do not establish contents pages. Continuations require verified chapter entries. Nested bookmarks, including multiple entries on one physical page, remain searchable navigation entries. Exact matching text provides an interior anchor where available; otherwise the entry opens its verified source page.

Appendix labels such as A-12, Unicode decimal digits and dash variants resolve through printed-page lookup. Duplicate labels at different physical pages remain ambiguous. Facing-page scans can expose both printed numbers as aliases of the same source spread when consecutive footer numbers are recognized confidently on opposite sides; the scan remains a spread rather than two reconstructed text pages.

Small marginal footnotes can continue across adjacent source pages. Endnote sections retain their text and link explicit bracketed or Unicode raised references when their marker is unique. Ambiguous reused markers and bare numbers remain unlinked; their source text stays readable. Notes and citations are not silently promoted to chapter boundaries.

## Validation

- `npm test`: chapter mapping, conflicting contents links, unknown numbers, numbering resets, Roman front matter, manual splits, OCR scoring and geometry, plus existing suites.
- `npm run typecheck`, `npm run build`, and `npx next build`.
- `npm run test:import`: Chromium and WebKit at phone size, using a real PDF with contents, front matter, offset printed numbering, and a scan with a sparse native footer. Checks OCR content recovery, confidence persistence, manual chapter creation, label correction, exact navigation, and review overflow.
- `npm run test:chapters`: Chromium and WebKit at 1440px, 390px and 320px widths. Uses a generated PDF with twelve wrapped, numberless linked chapters; checks complete names, editor geometry, native PDF links, search, and chapter jumps in original layout, Curl, Slide and Scroll. Scroll jumps are checked against the actual heading position.
- `npm run test:reading-layout`: Chromium and WebKit at desktop, phone, small-phone and landscape sizes. Seeds an old flattened contents paragraph, checks separate linked rows without a drop cap, verifies unchanged stored text/page marks, and exercises quotes, line breaks, long tokens and heading pagination.
- `npm run test:fidelity`: Chromium and WebKit at phone size. Imports 48 illustrations and a vector financial table, checks all 49 saved crops, exact numeric cell text and emphasis ranges, then opens enlargement and the correct original page.
- `npm run test:edge-import`: Chromium and WebKit imports covering verse, code, dialogue, nested lists, text-only tables, equations, three-column prose, raised text, RTL text layers, multilingual contents, nested bookmarks and endnotes. Checks character retention at phone/desktop sizes, paginated/Scroll rendering, original-page enlargement, note popups, mixed English/Spanish recognition, misleading hidden text, facing-page aliases and unlocked password-protected source renderings. Fixtures are synthetic; the encrypted fixture uses the test password `reader-test`.
- `npm run test:auto-ocr`: Chromium and WebKit verify that unchecked OCR does not load the recognition worker for native/blank pages, recovers text from full scans and footer-only scans, and displays the automatic-recognition notice in the unchecked import workflow.
- `QA_DEVICE=phone npm run test:pdf`: existing blank/title/text PDF import, notes, bookmarks, reload, themes, and reflow checks in Chromium and WebKit. On PowerShell, set `$env:QA_DEVICE='phone'` before running the command.

The October 30 validation also inspected and extracted a 241-page text/image source and a 187-page scan locally. The linked source resolved all fourteen main chapters with complete names; the scan resolved all six numbered contents entries, including multi-line headings and italic OCR page digits. Source PDFs and extracted book text are not committed as test fixtures.

Browser artifacts are written to ignored `work/import-qa`, `work/chapter-qa` and `work/reader-qa`. These tests do not establish accuracy for every book, physical-device behavior, or the live deployment.
