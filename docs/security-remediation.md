## Runtime limits

- 100 books / 24 MiB aggregate book JSON per account.
- 10,000 annotations / 8 MiB aggregate annotation JSON per account.
- 2,000 objects / 500 MiB reserved bytes per account; 20 MiB per uploaded object.
- Upload reservations deliberately retain the highest reserved size for an ID until deletion. Failed/replaced uploads can reserve more space than the stored bytes; deletion releases reservations. Existing objects need reconciliation.
- Auth: 300 requests/minute globally, 30/IP/minute, 20 app signups/day globally. These are conservative defaults for a small deployment; configure edge controls and tune deliberately for actual traffic.
- Session lookups: 240/minute/Cloudflare client IP, including invalid tokens. Library writes: 30/minute/account; sync: 120; upload: 10; downloads: 120; library pages: 240; deletion: 20.
- Backups: at most 55 MiB binary attachments when exporting, 80 MiB plaintext before encryption, 115 MiB import file. Exports are a bounded full archive, not a streaming backup of the entire 500 MiB cloud quota.

## Rollout order

1. Use an isolated Neon branch and private staging bucket. Revoke/rotate the credentials identified in the original audit. Never copy their values into logs, source, build output or this document.
2. Supply a migration-administrator `MIGRATION_DATABASE_URL` to `npm run db:migrate`. The runner applies `db/folio.sql` transactionally. It no longer falls back to `DATABASE_URL`.
3. Apply `db/runtime-role.sql` once as the administrator, assign a new password through Neon, and set the Worker's `DATABASE_URL` to that restricted role. Do not grant owner-role membership or BYPASSRLS. Keep the migration connection out of the Worker environment.
4. Reconcile pre-existing objects using storage HEAD/list metadata into `folio_files` (including orphan uploads); review legacy oversize or unsafe files and existing accounts above quota. Do not silently discard data. Scope replacement S3 keys to `folio-books` only.
5. Configure provider email verification, exact trusted origins, reset/OTP limits and session revocation. Configure edge rate limits/CAPTCHA. Schedule deletion of expired `folio_rate_limits` rows, e.g. `DELETE FROM folio_rate_limits WHERE window_start < now() - interval '2 days'`, using a maintenance role; the runtime role cannot perform this maintenance.
6. Build and deploy the matching schema/client/Worker together. The API intentionally stops accepting bearer JWTs, requires verified email, uses paging, and lowers uploads from 50 MiB to 20 MiB. Existing clients must reload the updated service worker/app.
7. Use two empty verified staging accounts and `READWIND_ALLOW_CLOUD_TESTS=staging-only` with `READWIND_TEST_EMAIL_A/B` and `READWIND_TEST_PASSWORD_A/B` to run `npm run test:cloud`. Keep these in the process environment only. Also validate real provider revocation, reset emails, trusted origins, storage quota reconciliation and provider deletion cleanup before production rollout.

## Local verification

- Unit/regression tests cover forged session_data, live session validation, bearer rejection, invalid origins, traversal, missing/false body lengths, malformed JSON, active/remote backup attachments, schema bounds and authenticated encryption/tampering.
- Embedded PostgreSQL tests execute the actual migration and runtime-role SQL, then check tenant isolation, rejected foreign writes, denied DDL, quota enforcement and cascaded deletion. Concurrency and provider behavior still require staging checks.
- Browser security test: `node scripts/test-security-browser.mjs` against a local production server. Provider/API calls are mocked for authenticated UI checks. Verifies paging, malicious restore without LAN requests, sign-out cache deletion during an in-flight sync, headers on real Worker/static responses and anonymous API denial.
- Additional production-browser checks cover responsive library/notebook, PDF import/notes/bookmarks/reflow and offline reopen.
- No production database, S3, Neon configuration or deployment was modified in this remediation session. Only local secret-file ACLs were changed. The local production preview is for verification, not a deployment.
